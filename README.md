# CMAC — Centralized Monitoring, Analytics & Control

An AI-powered, **fully software** railway management platform. No physical
sensors, cameras, or microcontrollers are used anywhere in this project —
all "live" data is sourced from public datasets/APIs or the simulator
scripts in `backend/simulator/`, so the entire system runs on a laptop or
a free-tier cloud instance.

Built by **Hari** — Stranger Nerds United (SNU) · `#30DaysOfAI`

---

## What's inside

| Layer | Folder | Description |
|---|---|---|
| Data Source / Simulation | `backend/simulator/` | Generates realistic train GPS, crowd, and sensor data in place of real hardware |
| Backend API | `backend/` | FastAPI service: train tracking, crowd analytics, predictive maintenance, delay prediction, alerts |
| AI / ML | `backend/ml/` | Crowd density (OpenCV HOG detector), predictive maintenance (IsolationForest), delay prediction (RandomForest) |
| Frontend Dashboard | `frontend/` | React + Vite JARVIS-style live dashboard |
| Sample Data | `data/sample/` | Reference CSVs for trains and sensors |
| Report | `docs/` | Full project report (Word doc) |

## Architecture

```
Data Source / Simulation  →  Ingestion (REST API)  →  Storage (SQLite/Postgres)
        │                                                     │
        └──────────────► AI/ML models (crowd, maintenance, delay) ──┐
                                                                      │
                                              Alert Engine ◄──────────┘
                                                     │
                                     React Dashboard (live polling)
```

## Quick start (no Docker, fastest path)

### 1. Backend

```bash
cd backend
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env          # defaults work out of the box (SQLite, console alerts)
uvicorn main:app --reload --port 8000
```

The API is now live at `http://localhost:8000` — interactive docs at
`http://localhost:8000/docs`.

### 2. Start the simulators (in a second terminal)

```bash
cd backend
source venv/bin/activate
python simulator/run_simulator.py
```

This streams simulated train movement, crowd footfall, and sensor data
into the API continuously — standing in for real-world feeds.

### 3. Frontend

```bash
cd frontend
npm install
npm run dev
```

Open `http://localhost:5173` to see the live CMAC dashboard.

## Quick start (Docker)

```bash
docker compose up --build
```

This brings up Postgres, the backend (port 8000), and the frontend
(port 5173) together. Run the simulator locally against the containerized
API (`python backend/simulator/run_simulator.py`) to populate live data.

## API overview

| Endpoint | Method | Purpose |
|---|---|---|
| `/api/trains/` | GET | List all tracked trains |
| `/api/trains/update` | POST | Upsert a train's position/status (used by simulator) |
| `/api/crowd/ingest` | POST | Record a crowd density reading, auto-alerts if over threshold |
| `/api/crowd/latest` | GET | Recent crowd readings |
| `/api/maintenance/sensor` | POST | Record + score a sensor reading (anomaly detection) |
| `/api/maintenance/readings` | GET | Recent sensor readings |
| `/api/delays/predict` | POST | Predict delay (minutes) for given trip conditions |
| `/api/delays/recent` | GET | Recent delay predictions |
| `/api/alerts/` | GET | Unified alert feed |
| `/api/alerts/{id}/acknowledge` | POST | Acknowledge an alert |

Full interactive documentation is auto-generated by FastAPI at `/docs`.

## Swapping simulated data for real sources (production path)

This project is intentionally structured so each simulated data source can
be swapped for a real one without touching the rest of the pipeline:

- **Train tracking** — replace `simulator/train_simulator.py` with a poller
  against a real GPS/schedule API (e.g. NTES-style feeds); keep posting to
  the same `/api/trains/update` endpoint.
- **Crowd analytics** — feed real CCTV frames into
  `ml/crowd_density.count_people_in_frame()` instead of
  `simulator/crowd_simulator.py`. For higher accuracy, swap the built-in
  OpenCV HOG detector for a YOLOv8 person-detection model — the function
  signature (frame in, integer count out) stays identical.
- **Predictive maintenance** — retrain `ml/predictive_maintenance.py` on
  real historical sensor data once available, in place of the synthetic
  generator.
- **Delay prediction** — retrain `ml/delay_prediction.py` on real
  historical schedule/delay records.

## Tech stack

- **Backend:** FastAPI, SQLAlchemy, SQLite (dev) / PostgreSQL (prod)
- **AI/ML:** OpenCV (crowd detection), scikit-learn (IsolationForest, RandomForest)
- **Frontend:** React 18, Vite, Recharts, Axios
- **Notifications:** console (default) / Twilio SMS (optional)
- **Deployment:** Docker Compose
